# OpenMV H7 Plus 扑克牌识别：混合定位版

板端使用以下四个文件：

- `cards_fast_config.py`：存储介质、唯一模板路径、相机方向和公共尺寸；
- `cards_hybrid_core.py`：LAB 定位、局部 Otsu 归一化、模板加载和判决；
- `capture_cards_hybrid.py`：模板采集入口；
- `recognize_cards_hybrid.py`：触发识别和 USB 诊断输出入口。

旧模板与本版不兼容。本版继续使用 `cards_fast_config.py` 中唯一的
`cards_fast_v1` 路径，不建立 v2 路径。开始采集前，应先归档或清空所选介质
下 `cards_fast_v1/templates` 内的旧 `.pgm/.json`；程序检测到旧签名时会停止，
避免新旧模板混用。`USE_SD_CARD=True` 使用 `/sdcard/cards_fast_v1`，设为
`False` 使用 `/flash/cards_fast_v1`。相机参数仍只保存在 Flash 的小型 JSON 中。

## 采集流程

1. 将配置、核心和采集程序复制到 OpenMV。需要重新标定相机时，仅第一次把
   `CALIBRATE_CAMERA=True`；其后改回 `False`。
2. 保持实际工作时的补光、曝光、安装距离和相机方向。调整 `CAPTURE_ROIS`，使
   机械极限位置下完整角标始终在框内。框可以包含少量中央花纹。
3. 普通牌设置 `CAPTURE_KIND="normal"`、点数和花色标签。采点数时使用
   `NORMAL_SAVE_GROUPS=("rank",)`，采花色时改为 `("suit",)`。
4. 每个点数和每种花色各保留两张模板：一张靠近机械运动范围的一端，另一张
   靠近另一端或具有代表性的光照状态。程序默认限制每标签最多两张。
5. 大小王都设置 `CAPTURE_KIND="joker"`；两者字形模板标签相同，由
   `JOKER_COLOR` 和识别时的红色证据区分。建议红、黑各采一张。
6. 牌背设置 `CAPTURE_KIND="back"`，采一至两张。采集程序只保存小型归一化
   PGM 和 JSON，不保存原始 PPM/BMP。

按键前先看 IDE：红/蓝框是宽搜索区，绿框是最终候选，右侧是实际写入模板的
归一化图。采集 ROI 与识别 ROI 不要求坐标一致；二者使用同一套局部 Otsu
规范化，因此只要完整字符能被定位，位置变化会在模板比较前消除。

## 识别流程

`recognize_cards_hybrid.py` 默认要求 13 种点数、4 种花色、Joker 和牌背模板
完整，并限制每个标签最多两张。P9 下降沿触发后取得新图，普通路径依次执行：

1. 用 LAB 红/黑墨迹掩膜寻找多个候选；黑色阈值已针对现有图片中的绿青偏色
   放宽色度，同时收紧亮度以排除亮背景和点状反光。
2. 点数保留单字符候选，并只按严格的同行规则合并“10”；花色不做传递式合并。
3. 依据点数在上、花色在下、中心横向接近及颜色一致性选择最多两个布局。
4. 从原始灰度图的小候选框重新裁切，局部 Otsu 得到填充字形，再等比例归一化。
5. 先只比较 0°。分数或分差不足时，才在同一帧尝试 ±5° 和 Otsu 阈值偏移。
6. 使用原生平均绝对像素差计算范围为 0～1 的相似度；同时满足绝对分数、
   第一与第二名分差、布局和颜色条件才输出牌名；
   其余输出 `RESULT:UNKNOWN`。
7. 普通牌或 Joker 已形成可信正面证据时，牌背单模板不能覆盖正面结果；若
   正面只因分差不足，则输出 `UNKNOWN`，避免误报 `back`。

`UNKNOWN` 在 USB 终端输出结果和具体门限或定位原因：

```text
RESULT:UNKNOWN
REASON:SUIT_MARGIN=diamond,0.020<0.025;BACK_SCORE=back,0.843<0.860
```

只要存在已评分候选，USB 终端还会输出紧凑的 `INFO` 行。每组依次为标签、分数、分差和
是否通过门限（1 或 0）：

```text
INFO:R:K,0.941,0.173,1;S:diamond,0.906,0.020,0;B:back,0.843,0.000,0
```

识别后的调试框绘制完成后会调用 `frame.flush()`，因此无需等到下一次触发才在
IDE 中看到当前照片。IDE 图像只绘制 ROI 和候选矩形，不写类别、分数、原因或
耗时文字；这些信息通过 USB 输出。显式刷新放在结果输出和计时之后，不计入识别时限。

当前 `MAX_ATTEMPTS=1`，不会重拍。典型普通牌的首轮最多比较两个点数候选和
两个花色候选：模板库完整且每标签两张时约 68 次小图差异统计，图像只有 32×48
或 32×32。只有失败帧才进入细化。是否满足 1 秒必须以板端打印的
`PROFILE total_ms` 为准；主机 OpenCV 测试不能模拟 H7 的实际耗时。

## 当前 BMP 的初步结果

`python tests/evaluate_pok_hybrid.py` 会去除截图中饱和的 IDE 标注线，生成：

- `pok_hybrid_report.json`：逐图定位、留一分类、分数和分差；
- `pok_hybrid_preview/`：每张可定位图片的归一化补丁；
- `pok_hybrid_seed_preview/`：每标签至多两张的初选样本及清单。

现有 33 张普通牌截图中有 28 张形成有效布局；两个 Joker 均定位成功且红黑判断
正确。26 个具备另一张同标签参考图的点数样本留一分类为 26/26，正式的
0.80 分数和 0.05 分差门限接收 21/26，接收样本为 21/21 正确。花色为
27/28，门限接收 23/28，接收样本为 23/23 正确。

这些 BMP 已画入 ROI 线和绿框，原像素无法完整恢复；未定位样本中一部分是标注
线修补后与中央花纹粘连造成的。预览模板没有板端相机元数据，也没有牌背样本，
只能用于策略和阈值初测，不能复制到正式模板目录。最终准确率和拒识率应使用
采集程序直接从无叠加的传感器帧重新采样，再另放一批不入库的验证牌统计。
