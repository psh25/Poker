# 架构 v2 与 v1 的区别总结

> 对比基准：《发牌机大致架构 v1(1).docx》  
> 更新依据：《与 AI 的部分对话.docx》、《ESP32-S3-WROOM-1-N16R8 底板软件开发交接指南.docx》

> ⚠️ 2026-09-08 修订：本文“硬件落地”部分写于 v2.1；自 v2.2 起，底座步进回归参考程序 **STEP/DIR/ENN**（移除 TMC 单线 UART / DIAG / INDEX / STDBY），滑环串口引脚改为 **POS/NEG**，子板调试 RGB LED 已移除。当前引脚与实现以 `architecture_v2.md` 1.3/8.2 及两板 `include/pins_config.h` 为准，下文硬件条目请结合该修订阅读。

## 一、总原则

v2 **不推翻 v1 的主体设计**，保留：4 状态状态机（IDLE / DEALING / GAME_ACTIVE / GAME_END）、底板 RTOS 任务集合主体、队列/信号量/互斥量/事件组四类 ITC、异常处理框架、启动顺序框架。

> 2026-08 修订：删除 SELECTING，选方案并入 IDLE：旋转切换方案（旋转即取消已确认）→ 短按确认方案 → 再次短按（CONFIRM）发牌。

本次修订只做两类整合：

1. **兑现此前与 AI 对话中已达成、但 v1 尚未完整体现的结论**（子板裸机、逐张实时上报、任务触发方式统一、屏幕事件驱动细化）。
2. **落地交接指南的硬件事实**（ESP32-S3 IO 映射、电源架构、TMC2209 规范、归零算法、整机保护），使架构从“大致架构”变为“可直接指导开发”的版本。

## 二、保留不变的部分

| 模块 | v2 的处理 |
|------|-----------|
| 状态机（4 状态 + 转移条件） | 删除 SELECTING，选方案并入 IDLE（两段式确认）；保留 GAME_ACTIVE → DEALING“补发牌”预留分支 |
| 任务列表主体 | 蓝牙、编码器、子板通信、发牌控制、屏幕显示、状态管理六任务保留，职责基本不变 |
| 队列/互斥量/事件组 | 名称与保护对象不变；`xDisplayQueue` 容量按对话结论由 10 调整为 5 |
| 信号量 | 三个信号量保留，触发源从“底板直连硬件中断”调整为“子板协议事件解析后 Give” |
| 异常处理 | v1 五条全部保留，分工按新架构明确 |
| 屏幕事件驱动 | v1 已体现为队列触发，v2 补充命令枚举、队列容量 5、非阻塞发送等实现约定 |

## 三、主要变化

### 1. 子板从“RTOS 任务”改为“裸机状态机”（唯一结构性调整）

- v1 将光敏检测、发牌控制、摄像头采集描述为底板 RTOS 任务（标注“/子板”）。
- 对话结论：子板工作量是串行流水线，无需 RTOS，**裸机超级循环 + 中断**更优。
- v2 将这三项职责移出底板任务表，交给子板裸机状态机；底板只保留“子板通信任务 + 发牌控制任务”作为编排入口，并新增独立的子板架构文档。
- ⚠️ 这是 v2 中**唯一的结构性调整**，虽源自此前对话结论，仍请审核确认后再进入开发。

### 2. 新增“底板 ↔ 子板通信协议”章节

- 物理层：滑环差分串口，CRC 校验、短包分帧、掉线超时保护。
- 原则：**子板 → 底板逐张实时上报，底板 → 小程序整局统一上传**。
- 草案命令/事件表（`EVT_CARD_OUT`、`EVT_CARD_VALUE`、`EVT_ERROR_CARD_JAM` 等）。

### 3. 硬件落地（v1 完全没有硬件细节）

- 新增底板 ESP32-S3 完整 IO 映射表（28 个引脚/网络）。
- 新增电源架构（7.4V → 6V/5V/12V/3.3V）。
- 新增 TMC2209 步进驱动开发规范（v2.1 曾计划单线 UART / DIAG / INDEX / STDBY；v2.2 起回归 STEP/DIR/ENN，电流由驱动板 VREF 电位器设定）。
- 新增霍尔两段式归零算法、EC11 消抖、屏幕 + SD 共用 SPI 的片选互斥约定。

### 4. 新增“系统监控任务”（低优先级，周期触发）

- 职责：周期巡检电机状态 / 滑环通讯心跳 / 告警（v2.1 草案中的温度 / `SG_RESULT` 读取因不再使用 UART 而取消）。
- 来源：交接指南要求“定时读取 TMC 芯片温度、SG 堵转数值，触发过热/堵转紧急停机保护”，v1 无此任务。
- 影响：底板自有任务数由 6（剔除 v1 中归属子板的光敏/摄像头任务）增至 7，属小幅新增。

### 5. ITC 触发源调整

| 对象 | v1 | v2 |
|------|----|----|
| `xCardDetectedSem` | 底板光敏 ISR 直接 Give | 子板通信任务解析 `EVT_CARD_OUT` 后 Give |
| `xDeckReadySem` | 子板摄像头识别完成直接通知 | 同上，由协议事件触发 |
| `xCameraQueue` | 生产者=摄像头采集任务 | 生产者=子板通信任务（解析 `EVT_CARD_VALUE`） |

等待语义与消费者不变，因此发牌控制任务逻辑无需结构性重写。

### 6. 异常处理扩充

v1 五条保留并明确分工（物理层异常子板检测上报、业务层决策底板负责），新增交接指南强制要求：

- 底座步进堵转/超时（软件超时 → ENN 断电 + 屏幕告警；DIAG 中断未接）
- 驱动过热（v2.2 起未实现：无 UART 读温度，依赖散热与电源裕量）
- 零点传感器失效（归零超时锁死电机）
- 滑环通讯掉线（暂停发牌等待恢复）
- INDEX 每圈失步校准（v2.2 起未实现：INDEX 引脚未接）
- 电机启停瞬间的传感器/串口抗干扰策略

### 7. 启动顺序整合

在 v1“硬件初始化 → 内核对象 → 任务 → 调度器 → IDLE”基础上，插入交接指南强制的：

1. 底盘步进初始化（AccelStepper，电流由驱动板 VREF 电位器设定）
2. 霍尔两段式自动归零
3. 外设自检（霍尔/编码器/SD/TMC/滑环）

### 8. 补充实现约定

- 任务触发方式统一表（每任务一种主要触发方式，超时仅用于异常检测）。
- 屏幕显示命令枚举（附录 A）、编码器事件结构（附录 B）。
- 待核对/遗留事项清单（附录 C）。

## 四、需要您审核确认的较大决定

| 序号 | 事项 | 说明 |
|------|------|------|
| 1 | 子板采用裸机架构 | 结构性调整，来自此前对话结论，建议确认后按此开发 |

## 五、源文档冲突 / 疑点记录

1. **IO10 归属冲突**：交接指南映射表定义 IO10 = EC11_SW，但“闲置 IO”列表又包含 IO10，需以原理图为准。
2. **蓝牙模块**：v1 硬件表写“蓝牙 UART/BLE”，交接指南未列独立蓝牙模块，v2 按 ESP32-S3 内置 BLE 处理。
3. **旋转电机类型**：v1 只写“旋转电机 GPIO/PWM”，交接指南明确为 TMC2209 步进驱动（底座转盘），v2 已更新。
4. **Micro USB 供电限制**：视觉模组与满载电机禁止使用 USB 口调试供电，开发调试时需注意。
