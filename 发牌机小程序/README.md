# 智能发牌机小程序

白色简洁主题 + 扑克花色装饰。通过蓝牙连接发牌机底板（ESP32 / 设备名 DealerBot），接收发牌/记牌信息，云端同步（可配置）。内置斗地主 AI 陪打（本地演示）。

## 一、使用步骤

1. 用**微信开发者工具**导入本目录。
2. 把 AppID 换成你**新注册的、支持云开发的号**：详情 -> 基本信息 -> AppID（或改 project.config.json 的 appid）。
3. 开通云开发，创建环境，把环境 ID 填到 miniprogram/config/index.ts 的 CLOUD.ENV_ID。
4. 在开发者工具里**上传云函数**：右键 cloudfunctions/sync -> 上传并部署：云端安装依赖。
5. 真机预览（蓝牙功能需真机；Android 首次扫描会请求定位权限，允许即可）。

> 没配云环境也能跑：自动进入“本地模式”，只记录在本机。AI 陪打是纯本地功能，任何时候都能玩。

## 二、蓝牙协议（二进制帧，与底板固件一致）

- 服务/特征：按课程讲义《网络通信蓝牙》NUS 标准
  - Service：6E400001-B5A3-F393-E0A9-E50E24DCCA9E
  - RX 写特征（手机 -> 底板）：6E400002-B5A3-F393-E0A9-E50E24DCCA9E
  - TX 通知特征（底板 -> 手机）：6E400003-B5A3-F393-E0A9-E50E24DCCA9E
- 载荷：**二进制帧**，与底板↔子板 UART 同一套
  `0xA5 | type | len | data(≤31) | crc8(type+len+data) | 0xAA`
- 一帧可能超过单次 BLE 写上限(20B)，小程序按 20B 分片写入，底板解析器可跨片重组。
- 上传计划的 `pileCount` 固定报 **8**（底板 `DECK_COUNT=8` 个实体牌堆位），牌堆号范围 **0~7**。
- 用 BLE 调试助手可直接发 hex 测试（例如选方案4+确认+发牌：
  `A5 10 03 <crc> AA`、`A5 11 00 <crc> AA`、`A5 01 00 <crc> AA`）。

### 手机 -> 底板（命令）
| type | 含义 | data |
|---|---|---|
| 0x01 | 启动发牌（仅 IDLE 且已确认） | 无 |
| 0x02 | 停机：发子板 STOP + 底板回 IDLE | 无 |
| 0x03 | 状态查询（回 0x91） | 无 |
| 0x04 | 子板自检（转发） | 无 |
| 0x05 | 复位：发子板 RESET + 底板回 IDLE | 无 |
| 0x10 | 选择方案（**模式 id = 底板方案索引，0~9 一一对应**） | [idx] 0~9 |
| 0x11 | 确认方案（两段式第一步） | 无 |
| 0x14 | 发牌计划开始 | [scheme,totalLo,totalHi,pileCount] |
| 0x15 | 发牌计划分块 | [offset,deckIndex...] |
| 0x16 | 提交发牌计划 | 无 |
| 0x13 | 线上出牌文本（显示到底板屏幕） | UTF-8 ≤31B |

### 底板 -> 手机（事件）
| type | 含义 | data |
|---|---|---|
| 0x90 | 命令回执（镜像 ACK） | 原 type + 原 data |
| 0x91 | 状态通知 | [state, scheme, confirmed]（底板状态机只有 **3 态**：0 待命 IDLE / 1 发牌中 DEALING / 2 牌局中 GAME_ACTIVE） |
| 0x92 | 发出一张牌 | [idxLo,idxHi,pile,suit,rank,simulated]（simulated:0真实/1模拟；suit:0♠1♥2♣3♦4王；rank:3~15=3…2,16小王,17大王） |
| 0x93 | 整轮发完 | [total] |
| 0x94 | 记牌（GAME_ACTIVE 编码器短按，p 自动 0→1→2） | [p, suit, rank]（牌面未知=FF） |

> 发牌流程：手机 0x10(选) → 0x14/0x15/0x16(完整下发计划) → 0x11(确认) → 0x01(发牌) → 底板每发一张回 0x92，发完回 0x93 → 状态 0x91。

| id | 名称 | 板端参数 | 计划来源 |
|---|---|---|---|
| 0 | 斗地主 | 3×17 + 底 3（54） | 手机下发 |
| 1 | 掼蛋 | 4×27（两副 108） | 手机下发 |

| 3 | 德州6人 | 6×2 + 公共 5（52，余 35 进弃牌堆） | 手机下发 |
| 4 | 桥牌 | 4×13（52） | 手机下发 |

## 三、页面

- **首页**：扫描/连接 DealerBot、选择方案（10 项，与底板方案表一一对应）、上传完整发牌计划、开始发牌、逐张显示本次所有牌面、复位/停机。
- **牌局**：发牌进度（逐张 0x92 更新，不暴露他人牌）、记牌（已打出 + 剩余）、线上（只看自己的堆，出牌以文本经 BLE 显示到底板屏幕）、AI（斗地主本地陪打演示）。
- **历史**：本地牌局列表，可拉云端。
- **评审页**：完整牌序/各堆/打出记录，仅评审可见（从历史进入）。

## 四、隐私与记牌流程

- 玩家端**不显示**别人的手牌；整副记录只在评审页展示。
- 记牌：玩家把打过的牌放回发牌机 -> 现场在 GAME_ACTIVE 按一次**编码器**（玩家号 0→1→2 轮流） -> 底板识别并蓝牙上报 0x94 played -> 手机记录并（云可用时）同步。
- 线上第三人：出牌 -> 云端 -> 现场手机轮询 -> 经 BLE 0x13 显示到底板屏幕。

## 五、AI 陪打（斗地主）

- 算法在 miniprogram/utils/doudizhu.ts：牌型识别（单/对/三带/顺子/连对/飞机/炸弹/王炸等）、一手牌枚举、主动出牌与跟牌策略（权重 + 拆牌惩罚），纯本地毫秒级计算。
- 牌局页 AI 分段即可玩：你当地主先出，两个 AI 自动跟牌/要不起；也可以随时点**提示**让 AI 给你建议。

## 七、扫描不到 DealerBot

1. 必须使用真机预览，微信开发者工具模拟器不能进行 BLE 扫描。
2. 打开手机蓝牙、定位服务，并允许微信使用蓝牙和位置权限。
3. 确认底板已通电且串口出现 `[BLE] init 'DealerBot' service=6E400001-...` 与 `[BLE] adv interval 100 ms`。
4. 广播间隔已放宽到 100 ms（省电），**发现会比以前慢一点**：多等几秒或再扫一次。
5. 如果其他手机/调试助手上还连接受发牌机，先断开，再重启底板。
6. 小程序会优先显示名称或 NUS Service 匹配的设备，并把发牌机排在列表前面。
