# 多功能发牌机（Dealer Machine）

本项目是一个基于 **经典 ESP32 底板 + ESP32-S3 上层子板** 的多功能发牌机：通过旋转编码器选择发牌方案（德州扑克、斗地主、桥牌等），自动旋转底座、逐张发牌，用摄像头记录牌面、光电门校验发牌结果，并通过蓝牙与小程序联动，支持远程参与牌局。

> ⚠️ **本 README 与其它文档只描述结构，不复述具体引脚号**；底板与子板的引脚一律以各自 `include/pins_config.h` 为唯一真源。

## 硬件概览

| 部件 | 所属板 | 说明 |
|------|--------|------|
| 底座转盘步进电机 | 底板 | TMC2209 驱动（STEP/DIR/ENN，电流由驱动板 VREF 电位器设定）；转盘 8 个实体牌堆位 |
| 屏幕 + SD 卡 | 底板 | ST7735 128×160 面板（1.8"，横屏使用，逻辑 160×128），与 SD 共用 SPI 总线（独立片选；SD 暂未接线） |
| 旋转编码器 | 底板 | EC11：旋转选择/取消方案、短按确认方案/CONFIRM 发牌、**IDLE 长按切换发牌方式（顺序/随机）**、GAME_ACTIVE 长按结束回 IDLE |
| 霍尔零点传感器 | 底板 | A3144，两段式上电归零、运行中失步校准 |
| 蓝牙 | 底板 | ESP32 内置 BLE，与小程序通信 |
| 发牌电机 | 子板 | 6V 直流电机，由子板控制 |
| 光电门（原光敏） | 子板 | 有牌 = 低电平、无牌 = 高；等“有牌→无牌”确认牌完整通过，并做卡牌保护 |
| 摄像头 | 子板 | 识别牌面（花色、点数） |
| 板间通信 | 滑环 | **2 线 UART**（POS/NEG 各一线，POS 连 POS、NEG 连 NEG；引脚见两板 `pins_config.h`），CRC 校验 |

> ⚠️ IO 映射以两板的 `include/pins_config.h` 为最新标准，**开发/接线前必须与各自原理图逐项核对**；《底板软件开发交接指南》中的旧版引脚表已不再使用。

## 架构要点（v2）

设计文档：[整体架构 v2](docs/architecture_v2.md) · [v1→v2 差异](docs/architecture_v2_diff.md) · [子板架构](docs/subboard_architecture.md)

### 核心决策

- **底板：FreeRTOS 多任务**；**子板：裸机（超级循环 + 中断）**，子板是“带反馈的执行器”。
- **通信原则**：子板 → 底板逐张实时上报（光敏/识别/异常），底板 → 小程序整局统一上传。
- **板间协议**：`0xA5 | type | len | data | crc8 | 0xAA`，掉线超时保护（详见 [board_protocol.md](docs/board_protocol.md)）。
- **命令/事件命名**：命令统一 `CMD_*`，事件统一 `EVT_*`（错误事件为 `EVT_ERROR_*`）；CLI 别名 = 枚举名**去前缀 → 全小写 → 去下划线**（`CMD_DEAL_START`→`dealstart`、`EVT_ERROR_MOTOR_STALL`→`errormotorstall`），两端一致。
- **状态机**：`IDLE → DEALING → GAME_ACTIVE`（选方案并入 IDLE：旋转切换/取消、短按确认方案、再按 CONFIRM 发牌；GAME_ACTIVE 长按编码器确认结束并直接回 IDLE），仅状态管理任务负责切换（单写者）。
- **发牌中止**：主机 `stop` / `reset` 会置"中止请求"，正在执行的发牌（底盘转动、等待事件）会尽快退出并回到 IDLE，不再下发新命令。
- **掉线保护**：发牌前检查子板在线状态（心跳 1s、掉线阈值 3s），不在线直接拒绝启动并报 `sub offline`，避免白等一串超时。
- **无子板模式（子板仿真）**：底板与子板经常分开调试，底板串口敲 **`subsim on`** 即可进入无子板模式（`simauto` 是旧别名）。
  打开后：跳过"子板不在线"检查、**不下发动作类命令**（截图/发牌/停机/复位），每张牌的牌面、出牌成功、收尾完成由底板自己按 `SIM_*` 延时补发。
  默认关闭（真实方案一律走真实外设，避免模拟数据掩盖硬件故障）；要在上电时就默认开启，把 `app_config.h` 的 `USE_SUBBOARD` 改成 0。
- **发牌方案参数化**：方案 = 参数（人数 / 每人张数 / 公共牌 / 底牌 / 总牌数，超出部分算**弃牌**），预置斗地主/掼蛋/升级/德州6人/桥牌/测试 + 串口自定义；发牌任务只执行“发牌组列表”（转到位→连发 N 张→下一堆），新增玩法不再写发牌逻辑，详见 `include/deal_config.h`。
- **发牌方式（顺序 / 随机）**：与方案互斥独立，IDLE 下**长按编码器**切换，屏幕顶部 `Seq`/`Rand` 徽标常驻显示。顺序=按堆依次发（弃牌留在牌源）；随机=硬件随机数洗牌后按洗牌结果**无序**转堆发牌（整副牌全部发出，多余进弃牌堆）。
- **摄像头时序**：上一张发牌成功后，底板发 `CMD_CAM_CAPTURE` → 子板把 `PIN_CAM_TRIG` **拉低**（OpenMV P6 为**下降沿**触发，空闲保持高）截图 → 转盘转到目标牌堆 → 等待识别完成 → 再下发发牌指令。子板**只接收、不主动取图**：摄像头回传的 OpenMV 原生文本行（`RESULT:...`）在截图等待窗口内轮询接收，解析成牌面编码后转发 `EVT_CARD_VALUE`；未回传时按“发空牌”继续（调试路径）。
- **子板心跳**：底板每 1s 发 `CMD_STATUS_QUERY`，子板回 `EVT_STATUS`；3s 内无任何子板帧判定掉线，底板 CLI `subboard` 可查询。
- **屏幕显示**：事件驱动（队列触发），非轮询，**只展示不决策**——菜单选中项 / 是否确认 / 发牌方式都存在 `deal_selection` 模块（互斥量保护），显示层不再保存业务状态。
- **中断 vs 轮询的分工**：**该用中断的用中断**——编码器 A/B 相 GPIO 中断四态解码、子板串口 RX 中断写环形缓冲（中断里只累加计数/写缓冲，不做解析与打印）；**该轮询的保持轮询**——光电门电平采样、摄像头 `Serial2` 回传、两板 CLI、监控巡检、步进 STEP 脉冲生成。判据：需要"电平已稳定多久"这类时间信息、或边沿中断容易被干扰反复触发（浮空引脚/电机干扰）的场合，轮询更稳。详见 `docs/architecture_v2.md` v3.4 修订。

### 底板任务与优先级

| 任务 | 优先级 | 核心 | 触发方式 | 关键时序 |
|------|--------|------|----------|----------|
| 蓝牙通信 | 高 (3) | 任意 | BLE 队列 + 帧解析 | NUS 服务，收主机命令帧/发状态帧 |
| 子板通信 | 中 (2) | 固定核心 0 | 串口中断 + 队列 | RX 中断写环形缓冲，任务 5ms 解析；掉线阈值 3s |
| 发牌控制 | 中高 (2) | 固定核心 1 | 信号量触发 | 光电门 1.5s、摄像头 2s 超时；每张等 `EVT_DEAL_DONE` |
| 编码器处理 | 中 (2) | 任意 | A/B 中断 + SW 轮询 | A/B 中断四态解码（4 跳变/格）；SW 5ms 轮询、10ms 消抖 |
| 屏幕显示 | 低 (1) | 任意 | 队列触发 | 事件驱动，队列容量 5 |
| 状态管理 | 低 (1) | 任意 | 事件组阻塞 | 永久等待（协调器） |
| 系统监控 | 低 (1) | 任意 | 定时器 | 500ms 巡检电机状态/心跳/告警 |

## 底板代码框架说明

`BottomBoard/` 已具备可用的**基础交互**：屏幕方案选择（两段式确认）、编码器旋转/按键、串口 CLI 调试（`sub` / `sim` / `setstate` 等）均已实现；电机、霍尔、SD、蓝牙等硬件功能仍以空函数（`busy_*`）占位，并在代码注释中标注了对应的架构章节与时序。

| 文件 | 内容 |
|------|------|
| `include/pins_config.h` | IO 映射 |
| `include/app_config.h` | 优先级、栈大小、队列容量、时序常量 |
| `include/deal_config.h` / `src/deal_config.cpp` | 牌局参数预置表 + 自定义参数 → 发牌计划 |
| `include/deal_selection.h` / `src/deal_selection.cpp` | 发牌选择状态（方案 / 是否确认 / 顺序或随机），带互斥量快照 |
| `include/itc.h` / `src/itc.cpp` | 队列、信号量、互斥量、事件组创建 |
| `src/tasks.cpp` | 任务创建 + 子板通信 / 编码器 / 屏幕显示 / 系统监控 四个任务 |
| `src/tasks_deal.cpp` / `include/tasks_deal.h` | 发牌控制任务：执行发牌计划、错误处理、状态快照 `deal_get_status()` |
| `src/host_actions.cpp` / `include/host_actions.h` | 主机命令动作（BLE / CLI 共用）+ 蓝牙接收任务 |
| `src/cli.cpp` / `include/cli.h` | 调试串口命令行（`cli_poll()` 由子板通信任务周期调用） |
| `src/display.cpp` / `include/display.h` | 屏幕显示（只按显示命令绘制：IDLE 屏、发牌进度、错误、GAME_ACTIVE） |
| `src/state_machine.cpp` | 状态机与转移逻辑 |
| `src/protocol.cpp` | 子板 UART 协议（帧解析/发送/事件分发） |
| `src/hardware.cpp` | 硬件初始化、中断、步进驱动（AccelStepper）/归零/**外设自检** |
| `src/main.cpp` | 启动顺序 |

启动顺序：硬件初始化 → 创建内核对象 → 挂接中断 → **屏幕初始化（含上电自检色块）** → 步进驱动初始化（AccelStepper）→ 霍尔归零（以开机位置为零点）→ **外设自检** → 创建任务（低→高）→ IDLE。
屏幕初始化排在自检前面，是因为自检结果要画在屏幕上（自检汇总屏停留 `SELFTEST_SHOW_MS` 2s，之后被 IDLE 屏覆盖）。

## 注意事项

- Micro USB 调试口仅 4.6~4.7V，**禁止**给视觉模组和满载电机供电。
- 电机启停会产生强电磁干扰：传感器采样需消抖/多次采样，串口必须带校验。
- 串口接线：滑环 POS 连 POS、NEG 连 NEG（方向：底板 POS=TX → 子板 POS=RX；底板 NEG=RX ← 子板 NEG=TX；具体引脚见两板 `pins_config.h`），且**必须共地**；不要占用调试串口；给某块板烧录前先断开两板间的 RX/TX 线。
